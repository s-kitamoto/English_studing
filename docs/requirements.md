# 英単語・フレーズ学習アプリ 要件定義（v0.1 ドラフト）

作成日: 2026-09-08 / ステータス: レビュー待ち

---

## 1. 目的とスコープ

### 目的
Web閲覧中・業務中に出会った英語表現を **摩擦ゼロで記録** し、**忘れる直前に再会させる** ことで使える語彙にする。

### 対象範囲
- 単語 1語に限らず、**フレーズ / コロケーション / イディオム / センテンス** を同じ器で扱う
- 記録 → 意味・使い方の付与 → 間隔反復による復習 → 定着状況の可視化

### 非スコープ（初期版では作らない）
- 複数ユーザー / チーム共有（設計上は将来拡張可能にするが、初期は個人1名）
- ネイティブ音声の録音・収録（ブラウザ内蔵の音声合成で代替）
- モバイルネイティブアプリ（WebAppのレスポンシブ対応で代替）

## 2. システム構成

```
┌─────────────────────┐
│ Chrome拡張 (MV3)     │  選択テキスト → 右クリック / ショートカット
│  service worker      │──POST(text/plain)──┐
│  content script      │                    │
│  popup               │                    │
└─────────────────────┘                    ▼
                                 ┌──────────────────────────┐
┌─────────────────────┐          │ GAS Web App              │
│ ブラウザ (PC/スマホ) │──GET────▶│  doGet  : HtmlService(UI)│
│  学習UI              │          │  doPost : 拡張からの登録 │
│  Web Speech API 発音 │◀google. ─│  Enricher: 意味取得       │
└─────────────────────┘ script.run└──────────┬───────────────┘
                                              │
                                    ┌─────────▼──────────┐
                                    │ スプレッドシート    │
                                    │ Items / Reviews /  │
                                    │ Settings           │
                                    └────────────────────┘
                                              │
                                    （任意）外部API
                                    Gemini / Free Dictionary
```

### 技術選定と制約（調査結果）

| 項目 | 内容 | 出典/根拠 |
|---|---|---|
| GAS Web App の CORS | **OPTIONS プリフライトに非対応**。拡張から POST する際は `Content-Type: text/plain;charset=utf-8` にして「単純リクエスト」にする必要がある | Apps Script の既知制約 |
| GAS 実行時間 | 1実行 **6分**（無料/Workspace共通）。同時実行 30 | 2026時点の公式制限 |
| UrlFetch | 個人Gmail **20,000回/日** / Workspace 100,000回/日 | 同上 |
| トリガー総実行時間 | 個人 90分/日 / Workspace 6時間/日 | 同上 |
| スプレッドシート | 1000万セル上限。数千件の語彙なら余裕。ただし全件 `getValues()` の一括読み + `CacheService` 併用が前提 | — |
| `google.script.run` | 1往復 0.5〜2秒と遅い。**復習セッション開始時に出題分を一括取得**し、回答はバッチ送信する設計が必須 | 実測傾向 |
| 発音 | ブラウザ標準 `Web Speech API (speechSynthesis)` で英語読み上げ。**APIキー不要・完全無料** | — |

## 3. データモデル（スプレッドシート）

### 3.1 `Items` シート（語彙本体・1行1アイテム）

| 列 | 型 | 説明 |
|---|---|---|
| `id` | string | UUID。拡張・UI双方で生成せず GAS 側で採番 |
| `type` | enum | `word` / `phrase` / `idiom` / `sentence`。自動判定＋手動上書き可 |
| `text` | string | 英語表現そのもの（1語に限らない） |
| `lemma` | string | 検索・重複判定用の正規化キー（小文字化・冠詞除去・余分な空白除去） |
| `phonetic` | string | 発音記号（例: `/əˈkɒmədeɪt/`）※取得できた場合 |
| `pos` | string | 品詞（複数可、カンマ区切り） |
| `meaning_ja` | string | 日本語の意味（主）|
| `meaning_en` | string | 英英定義 |
| `usage_note` | string | 使い方・ニュアンス・類義語との違い・共起する語 |
| `example` | string | 例文（英） |
| `example_ja` | string | 例文の訳 |
| `tags` | string | カンマ区切り（`work` `meeting` `TOEIC` など） |
| `source_url` | string | 登録元URL |
| `source_context` | string | **登録時に選択箇所の前後を含めた原文**（文脈で覚えるため） |
| `encounter_count` | number | 同一表現に再遭遇した回数（重複登録時に加算＝重要度シグナル） |
| `status` | enum | `new` / `learning` / `review` / `mastered` / `suspended` |
| `due_date` | date | 次回復習日 |
| `interval` | number | 現在の間隔（日） |
| `ease` | number | SM-2 の易しさ係数（初期 2.5 / 下限 1.3） |
| `reps` | number | 連続正答回数 |
| `lapses` | number | 忘却（Again）回数 |
| `last_reviewed_at` | datetime | 最終復習日時 |
| `created_at` / `updated_at` | datetime | — |

### 3.2 `Reviews` シート（復習ログ・追記のみ）

`log_id` / `item_id` / `reviewed_at` / `grade`(0-3) / `mode` / `elapsed_ms` / `prev_interval` / `new_interval`

**別シートにする理由**: 将来 FSRS 等へアルゴリズムを差し替える際、過去ログがあれば再計算・パラメータ最適化ができる。月100件×3年でも約1万行で、シート容量的に問題ない。

### 3.3 `Settings` シート（key-value）

`daily_new_limit`(既定20) / `daily_review_limit`(既定100) / `enrich_provider` / `default_review_mode` / `tts_voice` / `webapp_shared_token`

※ **APIキーは Settings シートに置かず Script Properties に格納**（シートを共有した際の漏洩防止）。

### 3.4 type 自動判定ロジック

```
空白なし                                  → word
2〜4語 かつ 文末句読点なし                → phrase（動詞+前置詞の形なら idiom 候補）
5語以上 または 文末に . ? ! がある        → sentence
```
UI 上で常に手動変更可能。

### 3.5 重複登録の扱い
`lemma` が一致する既存行があれば **新規作成せずマージ**する。
- `encounter_count` を +1
- `source_context` / `source_url` を追記（最大3件まで保持）
- SRS 状態はリセットしない
- UI に「既に登録済み（3回目の遭遇）」と表示

### 3.6 同時書き込み
拡張からの `doPost` と WebApp からの書き込みが競合しうるため、書き込み処理は **`LockService.getScriptLock()` で直列化**する。

## 4. 復習アルゴリズム

### 選定: **SM-2（Anki 互換の4段階評価）**

調査したうえでの判断:

| 候補 | 評価 |
|---|---|
| **SM-2** | 数式が単純でGASで数十行。実績十分。**採用** |
| FSRS | SM-2 比で復習回数を20〜30%削減できるが、パラメータ最適化に機械学習が必要でGASでは非現実的。かつ **累計1,000レビュー未満ではデフォルトパラメータにフォールバックしSM-2と差が出ない**。ログを貯めておけば後から移行可能なので、初期採用の必要はない |
| Leitner（箱方式） | 実装は最も簡単だが間隔調整が粗い |

### 評価とスケジューリング

| 評価 | 操作 | 挙動 |
|---|---|---|
| **Again**(0) | 「わからない」 | 当日中に再出題（10分後キュー）。`ease -= 0.20`、`lapses++`、`interval` リセット |
| **Hard**(1) | 「あやふや」 | `interval *= 1.2`、`ease -= 0.15` |
| **Good**(2) | 「思い出せた」 | `interval *= ease` |
| **Easy**(3) | 「余裕」 | `interval *= ease * 1.3`、`ease += 0.15` |

- 初回: Again→10分 / Hard→1日 / Good→1日 / Easy→4日
- `ease` 下限 1.3
- 間隔に ±5% のランダムゆらぎを加える（同日に復習が集中する「雪崩」防止）
- `interval >= 180日` かつ `lapses == 0` で `status = mastered`

### 1日の負荷制御
新規は既定 **20件/日** に制限。復習が溜まりすぎる「レビュー雪崩」を防ぐ（学習アプリ全般で20件前後が上限とされる）。上限は Settings で変更可。

## 5. 復習モード（type に応じて出題を変える）

「1語に絞らない」という要件は、**出題形式をtype別に切り替える**ことで満たす。

| モード | 内容 | 主な対象 type |
|---|---|---|
| **フラッシュカード** | 表(英)→裏(意味・例文)。自己採点4段階 | すべて |
| **4択** | 誤答選択肢を **同タグ・同品詞の既存アイテムから自動生成**。新規カードのウォームアップ用 | word / phrase |
| **タイピング** | 日本語→英語を打つ。綴り想起は記憶効果が最も強い | word / phrase |
| **穴埋め (Cloze)** | 例文中のターゲットを空欄にして補充。文脈ごと想起させる | phrase / idiom / sentence |
| **並べ替え** | 単語チップをドラッグして文を組み立てる | sentence |
| **リスニング** | `speechSynthesis` で読み上げ → 綴り or 意味を答える | すべて |

### タイピング判定の正規化
大小文字・前後空白・連続空白・句読点・冠詞(a/an/the)の有無を無視して判定。
**Levenshtein距離1以内なら「惜しい（タイポ扱い）」**として正解＋綴り注意の表示。

### セッション設計
1セッション既定 **20問**。開始時に対象を一括取得し、回答はセッション終了時（または5問ごと）にバッチ送信。`google.script.run` の往復レイテンシを隠蔽する。

## 6. WebApp UI

### 方針
- **モバイルファースト**（スマホの隙間時間での復習が主用途）
- ダークモード対応、タップ領域を大きく、即時フィードバック（正誤の色・アニメーション）
- PCではキーボードショートカット（`Space`=めくる、`1`〜`4`=評価、`Enter`=次へ）

### 画面

| 画面 | 内容 |
|---|---|
| **ホーム** | 今日の復習件数 / 新規件数 / 連続学習日数(streak) / 直近8週のヒートマップ / 総登録数 / 「復習を始める」CTA |
| **登録 (Add)** | 英語表現を入力 → 「意味を取得」→ 候補が自動補完 → 編集して保存。type / タグ / 例文 / 出典を編集可 |
| **一覧 (Library)** | 全文検索、タグ・type・status での絞り込み、並び替え（登録日 / 次回復習日 / 遭遇回数）、インライン編集、削除、CSVエクスポート |
| **復習 (Review)** | 進捗バー、カード表示、4段階評価ボタン、発音ボタン、「この場で編集」、セッション終了サマリ |
| **未整備キュー** | 意味が空のまま登録されたアイテムだけを一覧し、まとめて埋める |
| **設定** | 1日の上限、既定の出題モード、意味取得プロバイダ、TTS音声（US/UK）、APIキー登録 |

## 7. Chrome 拡張（Manifest V3）

### 機能
- `contextMenus`: 選択テキストを右クリック →「英語帳に追加」
- `commands`: ショートカット（既定 `Alt+S`）で選択テキストを即登録
- content script: **選択範囲を含む前後の文** を取得して `source_context` に保存
- popup: 手動入力フォーム＋直近5件の登録履歴＋「意味を取得」
- 登録完了トースト表示（成功/重複/失敗）

### 通信
```js
fetch(WEBAPP_URL, {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' }, // ← プリフライト回避
  body: JSON.stringify({ token, text, url, context })
});
```
`host_permissions` に `https://script.google.com/*` と `https://script.googleusercontent.com/*` を指定（GASは302リダイレクトするため両方必要）。

### 認証（2案）

| 方式 | 内容 | 評価 |
|---|---|---|
| **A. 共有トークン方式（推奨）** | Web App を「全員（匿名含む）」で公開し、リクエストに固定トークンを付与。GAS 側で Script Properties のトークンと照合 | 実装が単純。拡張のソースからトークンは読めるが、**個人利用なら実用上十分**。漏洩時はトークン再発行で対処 |
| B. OAuth 方式 | `chrome.identity.getAuthToken` で Google OAuth → Sheets API を直叩き（GAS Web App を経由しない） | CORS問題なし・認証が堅牢。ただし GCP で OAuth クライアントID と拡張ID固定が必要で手間が増える。意味取得のサーバー処理は別途必要 |

→ **初期は A、必要になれば B に移行**。

## 8. 意味・使い方の自動取得（要件どおり2系統を用意）

`Enricher` を **インタフェース化**し、Settings の `enrich_provider` で切り替える。両方実装しておき、後から選べるようにする。

### 8.A APIキー不要版

| 手段 | 取得できるもの | 制約 |
|---|---|---|
| **`LanguageApp.translate()`**（GAS標準サービス） | 日本語訳 | **APIキー不要・無料**。単なる機械翻訳で、品詞・複数語義・ニュアンスは出ない。フレーズ/センテンスには十分実用的 |
| **Free Dictionary API** (`api.dictionaryapi.dev`) | 英英定義・発音記号・音声URL・例文・類義語 | **キー登録不要**（ただし外部APIではある）。英英のみ。コミュニティ運営で可用性の保証なし → **必ずキャッシュし、失敗時は空欄で保存** |
| Google Sheets `=GOOGLETRANSLATE()` | 日本語訳 | 数式ベース。値の固定化が別途必要で、上と比べて利点が薄い |
| **手動入力（文脈だけ保存）** | — | 自分で調べる過程自体に記憶効果がある。「未整備キュー」に溜めて後で埋める運用と相性が良い |
| 辞書サイトを開くだけ | — | 拡張の右クリックから Weblio / Cambridge を別タブで開く補助機能 |

→ **推奨構成: `LanguageApp.translate()`（日本語訳） + Free Dictionary API（発音記号・英英定義・例文）の併用**。どちらもキー登録が不要で、初期セットアップが最短。

### 8.B API使用版

| 手段 | 取得できるもの | コスト |
|---|---|---|
| **Gemini API (Flash系)** | 日本語の意味・品詞・**ニュアンス・使い方・類義語との違い**・例文2本＋和訳を **1回のリクエストでJSON生成** | 無料枠あり（※2025年12月に free tier が絞られ、モデル・アカウントにより日次上限の情報が割れている。個人利用ならおおむね足りるが要実測）。有料でも Flash 系は極めて安価 |
| DeepL API Free | 高精度な翻訳 | 月50万文字無料。辞書情報は出ない |
| Merriam-Webster Learner's Dictionary API | 学習者向けの良質な英英定義 | 無料枠 1,000回/日・非商用のみ |

→ **推奨構成: Gemini Flash 1本**。JSON スキーマを固定した構造化出力で `meaning_ja` / `pos` / `usage_note` / `example` / `example_ja` をまとめて埋める。**学習素材の質はこれが明確に最上位**（辞書APIでは「使い方」「ニュアンス」が埋まらないため）。

APIキーは **GAS の Script Properties にのみ保持**し、拡張機能側には置かない。

### 共通仕様
- 取得結果は Items シートに保存（＝キャッシュ）。同じ表現の2回目以降は外部呼び出しなし
- 取得失敗時も **登録は必ず成功させる**（空欄で保存 → 未整備キューへ）。取得失敗で記録が失われるのが最悪のUX
- 取得内容は必ず **保存前に編集可能**（自動生成を鵜呑みにしない）

## 9. 非機能要件

- **応答性**: 復習カードのめくり操作はサーバー往復を挟まない（クライアント側完結）。登録は3秒以内
- **可用性**: 外部API障害時も登録・復習は継続できる
- **データ可搬性**: CSVエクスポート。Anki 取り込み可能な形式（`text<TAB>meaning` 等）も出力
- **セキュリティ**: 匿名公開 Web App + 共有トークン。APIキーは Script Properties。個人情報は扱わない
- **バックアップ**: 日次トリガーでスプレッドシートのコピーを Drive に保存（世代7日分）

## 11. 判断が必要な事項

1. **意味取得**: 最初から Gemini（APIキーあり）でいくか、まずキー不要版で作るか（両方実装するが、Phase 2 でどちらを既定にするか）
2. **復習アルゴリズム**: SM-2 で確定してよいか（FSRS は将来移行可能な形でログだけ残す）
3. **利用アカウント**: 個人 Gmail か Workspace（`s-kitamoto@unext-hd.jp`）か。**Workspace ならクォータが 5倍で余裕があるが、組織のポリシーで Web App の外部公開や拡張機能のインストールが制限される可能性がある**（要確認）
4. **拡張の認証**: 共有トークン方式（A）でよいか
5. **UI言語**: 日本語UI前提でよいか
